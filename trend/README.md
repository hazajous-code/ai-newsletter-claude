# AI Trend Search (마케터용 주간 AI 트렌드 뉴스레터)

- 최신 호: `trend/index.html` → Pages 주소 `/trend/`
- 오늘의 AI 뉴스 탭: `trend/news.html` ← `trend/data/news.json`. 매일 07:00 KST `daily.yml`이 `scrape_daily.py`(수집) 후 `trend/curate_news.py`(선별: 글로벌 ≤6, 한국 ≤5, 기준 점수 미달 제외)를 실행해 갱신. 날짜별 아카이브는 `trend/data/news/YYYY-MM-DD.json` + `index.json`, 페이지에서 `news.html?d=YYYY-MM-DD`로 열람. 과거 스냅샷으로 재생성: `python trend/curate_news.py --backfill 30`
- 지난 호: `trend/issues/YYYY-MM-DD.html`, 목록은 `trend/archive.html`
- 조사 키워드: `trend/keywords.json` — `always`(상시)와 `focus`(이번 호 집중 주제)를 수정하면 다음 발행부터 반영
- 디자인: 흰 배경, `trend/style.css` 공통 사용

## 편집 원칙
- **메인 메시지:** 기능은 AI가 복제한다. 남는 경쟁력은 **고객의 의도를 파악하고 제품·메시지에 반영하는 일**. 매호 주제는 달라도 결론은 이 관점으로 연결한다.
- **매호 핵심 질문 하나**를 정하고, 네 섹션이 그 질문으로 이어지게 한다: 트렌드에서 질문을 세우고 → 사례로 가능성과 조건을 확인 → 체크리스트로 우리 상황을 판단 → TRY THIS로 작은 결과물을 만든다.
- 독자: 사내 마케팅·기획·제작 실무자 + 광고주 담당자. 같은 본문에서 역할별 결론(.roles: 실무자에게 / 광고주에게)을 따로 준다.
- 읽는 시간 8~12분. 핵심 트렌드 1개·사례 1개·실습 1개를 완성도 있게.

## 발행 절차 (자동 예약 작업이 따르는 규칙)
1. **조사 범위 분리**
   - 뉴스: keywords.json으로 최근 7일. 발표일과 실제 적용 시점 구분.
   - 사례: 기간을 넓혀 검증 가능한 사례 탐색(keywords.json의 `case_search`). 최신이 아니면 '재분석'으로 표시하고 이번 주 다시 다루는 이유를 밝힌다.
2. **구성 (순서 고정)**
   - 마스트헤드(히어로 카피 + 키워드 칩) → **3줄 요약**(알아둘 변화 / 적용 판단 / 이번 주 결과물 + 섹션 바로가기 + 읽는 시간) → EDITOR'S NOTE(핵심 질문, 짧게)
   - **01 주요 뉴스 / 트렌드:** 핵심 트렌드 1건을 `.frame` 태그로 **변화 → 근거 → 마케팅 영향 → 한계 → 판단(실험할 일 / 준비할 일 / 지켜볼 일)** 순서로. 고객 의도와 연결되는 신호 1건. 관련 브리프 2~3건(`.briefs`). 플랫폼 정책·기능 변경은 `.alert` 박스.
   - **02 적용 사례:** 실제 사례 1건(근거 충분하면 보조 1건). 배지(`.badge.real` 실제 사례 / `.badge.vendor` 공급사 공개 사례 / 재분석 여부)와 사례 카드 표(`.tbl.case`): 기업·시점·출처 / 해결하려던 문제 / 실제 적용 범위 / 드러난 고객 의도 / 작업 방식·사람의 판단 / 결과 / 측정 조건 / 한계. 이어서 '우리에게 적용한다면'(가상 예시는 가상이라고 표시)과 `.roles`.
   - **03 체크리스트:** 이번 호 사례와 직접 연결된 5~7개. 표: 확인할 것 | 완료 기준 | 권장 담당. 끝에 `.verdict`(시작 가능 / 준비 후 진행 / 이번에는 보류).
   - **04 TRY THIS:** 20~30분 실습 1개. `.spec`(목표·준비물·시간/난이도·결과물) → `.steps`(분 단위 순서) → 복사용 프롬프트(확인된 사실/추론 구분 필수) → 완료 기준(`.action`) → `.roles`(실무자 결과물 / 광고주 결과물) → 다음 단계 → '오늘 팀에 던질 질문'.
   - 용어 풀이(GLOSSARY) → 출처.
3. **사실·출처 원칙**
   - 브랜드·광고주·대행사 원문 발표와 공식 자료 우선. 솔루션 업체 고객 사례는 '공급사 공개 사례'로 표시.
   - 성과 수치는 비교 기준·측정 기간과 함께. 공개되지 않은 항목은 추정하지 않고 '미공개'. 소재를 많이 만든 것과 매출이 늘어난 것을 구분.
   - 실제 사례 / 가상 예시를 눈에 띄게 구분. 성과 보장 표현 금지. 확인되지 않는 내용은 넣지 않는다.
4. **표현**
   - 용어 풀이: 비전공자(문과생 마케터)가 모를 기술 용어는 첫 등장 시 <sup class="fn"><a href="#gN" id="rN" title="용어: 풀이">N</a></sup>로 번호를 달고, GLOSSARY(ol.gloss)에 1~2문장 비유 중심 풀이. 번호는 문서 등장 순서.
   - 사족 금지: 뉴스레터 자체를 설명하는 멘트('이번 호부터는~', '~를 목표로 합니다'), 연결용 문장('흥미로운 건~', '여기서 해볼 만한 질문이 있습니다', '~한 셈입니다', '~할 때입니다')을 쓰지 않는다. 문장은 사실이나 판단으로 바로 시작.
5. **발행 전 확인 질문**: 이번 호가 답하는 마케팅 질문이 한 문장으로 정리되는가 / 사례가 실제 적용을 확인할 수 있고 가상 예시와 구분되는가 / 수치 가까이에 근거 링크가 있는가 / 적용 가능·어려운 조건이 드러나는가 / 체크리스트와 실습이 사례에서 자연스럽게 이어지는가 / 실무자와 광고주가 각각 가져갈 결론이 있는가.
6. `issues/<날짜>.html` 생성, `index.html`을 최신 호로 교체, `archive.html`의 ARCHIVE:START 바로 아래에 한 줄 추가 → main에 커밋·푸시 → GitHub Pages 자동 배포.
