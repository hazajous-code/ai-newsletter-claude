01

리버스 엔지니어링 × AI — 깃허브발 '복제의 시대'

COVER STORY · focus 키워드
10월 첫 주 깃허브 트렌딩 상단은 새 모델이 아니라 "소스 코드 없이 남의 소프트웨어를 이해하고 다시 만드는" 도구가 차지했다. 정답 판정이 분명한 '매칭 디컴파일' 구조가 에이전트의 무한 반복과 맞물리며 게임 → 크리에이티브 툴 → 오피스로 복제 대상이 넓어지는 중.

왜 지금 가능해졌나

기존사람이 하던 리버스 엔지니어링

  • Ghidra·IDA 등 디컴파일러로 사람이 함수 하나씩 해석
  • 커뮤니티가 수년에 걸쳐 축적한 자원봉사 작업
  • 숙련도·시간이 진입장벽 → 소수 고전 게임 중심

'26년 10월~에이전트가 반복하는 리버스 엔지니어링

  • REA: 코딩 에이전트(Claude Code·Codex·Cursor) ↔ 디컴파일러 연결
  • 원본과 바이트 일치 여부로 합격/불합격 판정 → 사람 없이 수 시간 반복
  • 병목이 '숙련도'에서 '토큰 비용'으로 이동
  • MW2 복원 프로젝트: 3개월간 약 600~700억 토큰 사용(보도)

Always-on AI Agent — 그리고 메타 Muse

AGENTS
Google·Microsoft가 서비스형 에이전트를 먼저 발표했지만 초기 대상은 소규모 테스터·기업 고객 중심이었던 반면, Meta는 일반 소비자 대상 무료 중심의 Muse를 내놓고 인스타그램·광고 계정·커머스 연동까지 붙이며 대중화 경쟁에 불을 붙였다. Muse: 2주간 280만 다운로드, 앱스토어 1위

Always-on AI Agent 개념

'26년 초~Self-hosted AI Agent

  • 오픈소스 기반 Persistent Agent 확산
  • 사용자가 실행 환경을 직접 구축·관리
  • 인프라·모델·도구 구성은 자유롭지만 기술적 진입장벽과 운영 부담 존재
  • 대표: OpenClaw, Hermes 등

'26년 5월~서비스형 Always-on AI Agent

  • 주요 AI 플랫폼사의 관리형 에이전트 출시 본격화
  • 별도 구축 없이 목표·권한만 설정해 지속적 업무 위임
  • 편의성·접근성은 높지만 사업자가 제공하는 기능·연동 범위 안에서만 활용
  • 대표: Gemini Spark, Grok Bot, Meta Muse, OpenAI dots
